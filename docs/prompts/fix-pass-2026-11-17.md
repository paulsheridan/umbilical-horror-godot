## Workstream A — dim the two pickup markers by 1/3

### Original request

> The brightness/glow of the two current pickup markers should be turned down by 1/3 so
> they're easier to make out through the grainy camera.

### Files you own

- `src/ship/pickup_props.gd`
- `src/ship/beyond.gd`
- `tests/level_scene.gd`

### What to implement

1. Add one public constant in `pickup_props.gd`:

   ```gdscript
   const MARKER_BRIGHTNESS := 2.0 / 3.0
   ```

   Use it for every authored marker-glow value; do not scatter `0.6667` literals.

2. Apply the 2/3 factor to the marker glow only:
   - halo albedo alpha: `0.34` → `0.34 * MARKER_BRIGHTNESS` (≈ `0.2267`);
   - hover-ring albedo alpha: `0.85` → `0.85 * MARKER_BRIGHTNESS` (≈ `0.5667`);
   - local `OmniLight3D` energy: `0.85` → `0.85 * MARKER_BRIGHTNESS` (≈ `0.5667`);
   - `light_volumetric_fog_energy`: `1.2` → `1.2 * MARKER_BRIGHTNESS` (≈ `0.8`).
   Preserve the existing glow colours/hues. Do **not** change marker size, position, hover
   height, spin, pickup radius, collision, or visibility logic.

   The halo alpha is authored in **two** places: `halo()` sets `albedo_color` alpha `0.34`
   directly, and `indicator()` **overrides** that quad’s material with
   `Color(glow.r, glow.g, glow.b, 0.34)`. `halo()` is only called by `indicator()`, so the
   override is the value the player actually sees — changing only `halo()` would leave the
   marker at full brightness. Introduce a single
   `const HALO_ALPHA := 0.34 * MARKER_BRIGHTNESS` and use it in both places.

3. `beyond.gd` currently re-writes the lamp energy every frame:
   `lamp.light_energy = 0.85 * (0.82 + 0.18 * sin(...))`. That override would undo the new
   constructor value. Expose the base in `pickup_props.gd` (for example
   `const MARKER_LAMP_ENERGY := 0.85 * MARKER_BRIGHTNESS`) and use that constant in both
   places so the pulse tops out at the new base.

4. The unshaded floating model is deliberately separate from the halo. Leave its albedo
   unchanged unless inspection shows it is still clipping to a featureless white blob in
   the still/live feed; in that case scale only the *bright marker copy* (the `_glow(...)`
   materials created by `flashlight_model(true)` / `camera_model(true)`) by the same
   constant, and say so in your report. The base pickup models (`bright == false`) must not
   change.

5. Extend `tests/level_scene.gd` with value checks after the existing marker checks:
   - halo alpha is `is_equal_approx(PickupProps.HALO_ALPHA, ...)`; also assert that value is
     `is_equal_approx(0.34 * PickupProps.MARKER_BRIGHTNESS, ...)` so the factor is literal;
   - hover-ring alpha is `is_equal_approx(0.85 * PickupProps.MARKER_BRIGHTNESS, ...)`;
   - the `Glow` lamp energy is `is_equal_approx(PickupProps.MARKER_LAMP_ENERGY, ...)`.
   Also call `ship._animate_pickup_fx(0.0)` (or the appropriate public path) and assert the
   pulsed lamp energy never exceeds `MARKER_LAMP_ENERGY + 0.001`.

### Acceptance

- Exactly a 1/3 reduction in brightness, consistent between construction and the pulse.
- Both markers (flashlight and camera module) still exist, hover, spin, and hide/show with
  the pickup root exactly as before.
- `tests/level_scene.tscn` stays green.
- No changes outside the owned files.

## Workstream B — zombies reach their hands toward the drone while chasing

### Original request

> zombies should hold out hands toward the drone when they are in a chasing state as they run
> toward it.

### Files you own

- `src/host/host.gd`
- `src/host/stalker.gd`
- `scenes/actors/host.tscn` and/or `scenes/actors/stalker.tscn` **only if** a scene node is
  genuinely required (prefer runtime setup; keep scene diffs minimal).
- New `tests/zombie_reach.gd` + `tests/zombie_reach.tscn` (copy the runner pattern from
  `tests/stalker_ai.gd` / `.tscn`).

### Scope

- **Host (Kenney zombie, all Cold Hold hunters):** arms reach only in `State.STALK` while it
  is actually moving toward the drone. Patrol, curious, hunt, standing at hold distance, and
  losing sight return the arms to the authored clip.
- **Stalker:** arms reach in `State.CHASE` while moving toward the drone. Its existing
  stronger reach during `LURK`/`LUNGE` must remain unchanged.
- Do not change perception, speeds, catch range, animations, or state transitions.

### Host implementation guidance

The Host’s skinned animation is driven by `$Meshes/AnimationPlayer` on
`$Meshes/Model/Root/Skeleton3D`. Direct bone edits from `_physics_process` are overwritten by
the AnimationPlayer. Use a **post-animation hook**:

- Preferred: add `LookAtModifier3D` nodes at runtime as children of the skeleton, one each for
  `LeftArm`, `RightArm`, `LeftForeArm`, `RightForeArm`, targeting a runtime marker placed at
  the drone’s body (`drone.global_position + Vector3.UP * 0.45`). `LookAtModifier3D` is the
  built-in `SkeletonModifier3D` already used successfully for the Collector’s head in
  `collector.gd`. Its `forward_axis` takes one of the six axis-enum values (`0..5` =
  ±X/±Y/±Z), not an arbitrary vector: derive the arm down-the-limb direction from
  `forearm_global.origin - arm_global.origin` converted into the arm bone local space, then
  snap it to the nearest enum axis. The left/right arm rest bases are mirrored (their local
  +Z axes differ), so the two shoulders may need different axis values. Use angle
  limitations that keep the shoulders from folding backwards, and ramp `influence` from 0
  to 1 over ~0.2 s only while reaching.
- Fallback if `LookAtModifier3D` cannot produce a clean two-arm reach: add one small
  `SkeletonModifier3D` subclass/inner class that applies an additive local rotation to
  `LeftArm`/`RightArm` (and straightens `LeftForeArm`/`RightForeArm`) after animation. The
  same ramped influence/weight rule applies.
- Give the arms a slight shoulder-width split so both hands do not converge into one point
  (offset the left/right targets sideways by ~0.12–0.18 m).
- Expose a test-friendly `var reach_weight := 0.0` (0..1) updated each frame. It must be > 0
  only while `state == State.STALK` and horizontal speed is meaningful (use the existing
  `hspeed > 0.15` notion) and the drone is valid; otherwise decay it to 0.
- Keep the run gait in the legs. Do not disable the walk/run clip or freeze the body.
- Resolve bone indices defensively with `find_bone()`; if a bone is missing, leave the body
  unchanged rather than erroring.

Useful Host bone names: `Head`, `Neck`, `Chest`, `UpperChest`, `LeftShoulder`, `RightShoulder`,
`LeftArm`, `RightArm`, `LeftForeArm`, `RightForeArm`, `LeftHand`, `RightHand`.

### Stalker implementation guidance

`_animate()` already overrides `_arm_l`/`_arm_r`/`_elbow_l`/`_elbow_r` for `LURK`/`LUNGE`
with `reach = -1.05` and elbows `-0.55`. Add a `CHASE` branch after the normal walk/run arm
swing and before the LURK/LUNGE override:

- while `state == State.CHASE` and `Vector2(velocity.x, velocity.z).length() > 0.12`, lerp the
  arms toward a forward reach (roughly `-0.9` to `-1.1` on X) and elbows toward roughly
  `-0.5`, with a small gait-driven tremble so it does not look pinned;
- when chase stops or breaks, let the existing idle/walk targets take over.
- Do not alter `LURK`/`LUNGE` values.

Expose `var arm_reach := 0.0` (0..1) for the test if that makes the assertion cleaner.

### Test `tests/zombie_reach.gd`

Use a flat floor far from level geometry, instantiate the real prefabs, and a dummy
`CharacterBody3D` drone with `velocity` (Host sight needs motion; Stalker can be forced).

Host checks:
1. In patrol, wait ~20 physics frames: `reach_weight < 0.1`.
2. Place the dummy 5–6 m ahead, give it motion, `force_stalk(...)`, wait ~30 frames:
   `reach_weight > 0.6`.
3. Read `LeftHand`/`RightHand` world positions via
   `skeleton.global_transform * skeleton.get_bone_global_pose(bone)` and assert both hands
   moved toward the drone (distance to the drone decreased by at least ~0.15 m versus the
   patrol sample) and are in front of the chest.
4. Return to patrol / break sight and wait: `reach_weight` decays below ~0.1 and the hands
   return near their patrol positions.
5. Ghosted hosts never reach.

Stalker checks:
1. `force_chase()`, `_sees = true`, wait ~20 frames:
   `_arm_l.rotation.x < -0.55` and `_arm_r.rotation.x < -0.55` (or `arm_reach > 0.6`).
2. Return to patrol and wait: the arms return above roughly `-0.3`.
3. Confirm `LURK`/`LUNGE` still reach (existing behaviour; a light assertion is enough).

### Acceptance

- A chasing zombie visibly holds both hands out toward the drone while its legs run.
- It does not reach while patrolling, hunting by noise, standing still, or after losing the
  drone.
- No perception/catch/speed changes. New suite green.

> through/inside the zombie's head/face.

### Files you own

- `src/main.gd`
- `src/ui/hud.gd` **only if** a small HUD hook is unavoidable (prefer not to touch it).

  (`near = 0.04`, FOV normally copied from the drone camera).
- `_sync_feed_view()` follows `drone.cam.global_transform` every frame while live and writes
  `_feed_vp.render_target_update_mode = UPDATE_ALWAYS`.
- The HUD live shader shows that texture inside the optics window. `hud.set_static_amount()`
  overlays snow.
- `_on_drone_caught(host)` currently: sets `_reeling`, stops the drone, starts static, waits
  **1.6 s**, then frees the caught chassis. Do **not** lengthen that 1.6 s teardown window.

### What to implement

1. Add a one-shot catch-camera stage in `main.gd`, e.g.:

   ```gdscript

   const CATCH_FACE_MIN_FRAMES := 2
   const CATCH_FACE_FOV := 58.0
   const CATCH_FACE_CLEARANCE := 0.10  # metres outside the head surface
   var _catch_cam_active := false
   var _catch_cam_xform := Transform3D.IDENTITY
   var _catch_cam_fov := CATCH_FACE_FOV
   ```

2. `func _stage_catch_face(host) -> bool`:
   - Return false for non-zombies (the Processor is a maw, not a face; the Collector cannot
     catch). Only stage for:
     - **Host:** `host.get_node_or_null("Meshes/Model/Root/Skeleton3D")`, head bone `"Head"`.
       Head world transform is `skeleton.global_transform * skeleton.get_bone_global_pose(head_bone)`.
       The head bone’s local **+Z** is the face axis (the Collector’s `LookAtModifier3D` uses
       the same rig convention). The head centre is roughly the bone origin plus
       `head_basis.y * 0.09`; use a conservative head radius of **0.17 m**.
     - **Stalker:** `host.get_node_or_null("Rig/Hips/Torso/Head")`. The node origin is the
       skull centre; face axis is **-Z**; skull/jaw extent is about 0.24–0.26 m, so use a
       conservative head radius of **0.26 m**.
   - Pick a random direction in the **face hemisphere**: yaw within about ±0.6 rad and pitch
     within about ±0.45 rad around the face axis. Surface point =
     `head_centre + dir * head_radius`.
   - Camera position = `head_centre + dir * (head_radius + CATCH_FACE_CLEARANCE)`, plus a
     small random lateral offset (up to ~0.25 × head_radius) so different catches frame
     different parts of the face. Build a `Transform3D` that looks from the camera position
     at the surface point (add a small random roll). Set FOV `CATCH_FACE_FOV`.
   - Hard safety: `camera_pos.distance_to(head_centre) >= head_radius + _feed_cam.near + 0.02`.
     If a random pick violates it, push the camera outward until it does. This is what keeps
     the camera out of the head, not just a comment.

     `{head_centre, head_radius, face_point, cam_pos, cam_xform, host}`.
   - Return true and set `_catch_cam_active = true`, `_catch_cam_xform`, `_catch_cam_fov`,

3. `_sync_feed_view()` override, before the normal live branch:
   - while `_catch_cam_active`: force `_feed_vp.render_target_update_mode = UPDATE_ALWAYS`,

     `hud.set_feed_source(_feed_vp)`, then return. This must work even when
     `_camera_installed` was just cleared by the catch (the module is lost): treat
     `_catch_cam_active` as an override of `_live_feed_active()` for the duration.
   - after `_catch_hold` expires (count it down in `_process` using `delta`): set
     `_catch_cam_active = false`, leave the last face frame frozen by switching the viewport

     `_static_lock = 2.2` (or `maxf(_static_lock, 2.2)`). Play the existing `static` SFX at

   - Ensure `_catch_frames >= CATCH_FACE_MIN_FRAMES` before the freeze; if the hold timer

4. Wire `_on_drone_caught(host)`:
   - Stage the face **before** clearing `_camera_installed` and before the existing static
     lock. Only stage when a live feed is actually available at catch time
     (`_live_feed_active()`), so the still-only build does not show a phantom feed.
   - Move (do not duplicate) the existing immediate `_static_lock = 2.2` and `static` SFX:

   - Keep the existing `await get_tree().create_timer(1.6, false).timeout` exactly as long;

   - Clear `_catch_cam_active`/`last_catch_face` after the chassis is freed or the sortie is

   - The face beat is visual only: do not change catch rules, drone loss, module loss, fleet

5. Do not change the HUD shader unless a hook is unavoidable. If you touch `hud.gd`, keep the
